# 桌面版（Windows）

星临桌面版把服务器版的全部功能装进一个 Windows 软件：双击安装，后台窗口、特效页、连接直播间都在主播自己的电脑上运行，不需要服务器。和服务器版是同一套代码，新功能写一次两边都有。

- 支持：Windows 10、Windows 11（64 位）
- 下载：[GitHub 发布页](https://github.com/chrismaxluo/starfall/releases)，只下载 `Starfall-…-setup.exe`
- 安装包没有数字签名，Windows 会提示「Windows 已保护你的电脑」：点「更多信息」→「仍要运行」

## 和服务器版的区别

| | 服务器版 | 桌面版 |
|---|---|---|
| 后台登录密码 | 要 | 不要（只能在本机打开） |
| 谁能访问 | 任何能连上服务器的设备 | 只有本机；其他网站发来的请求一律拒绝 |
| 关闭窗口 | — | 缩到右下角托盘，特效照常播放 |
| 开机自动启动 | systemd | 新安装默认打开（开机后在托盘里运行，不弹窗口）；托盘菜单或「设置 → 桌面版」里可以关 |
| 更新 | 拉代码、构建、重启 | 有新版本时在管理后台顶部提示，点下载，下载完重启安装；正在直播时先不提示 |
| 特效页地址 | `http://服务器地址:17520/overlay/…` | `http://127.0.0.1:17520/overlay/…`（见下面「端口」） |
| 直播软件先打开 | 服务一直开着，不会遇到 | 特效页先显示透明的等待页，星临打开后自动连上（见下面「打开顺序」） |
| 素材快捷播放 | 在后台页面里点按钮、按快捷键 | 另外可以设全局快捷键（Ctrl / Alt / Shift + 键），在直播姬、游戏等别的窗口里按也能播放 |

托盘图标右键：打开星临、复制直播软件地址、开机自动启动、检查更新、打开数据文件夹、退出星临（正在直播时会先确认）。

托盘图标的提示文字显示当前状态（直播中一切正常、特效已暂停、B站登录失效等）。Windows 11 默认把托盘图标收在任务栏右下角的「^」里。

窗口：

- 记住大小、位置、所在屏幕和是否最大化；外接屏幕拔掉后回到主屏幕。
- 标题栏跟随管理后台的亮色 / 暗色。
- Ctrl 加号、Ctrl 减号或按住 Ctrl 滚动滚轮缩放管理后台，Ctrl+0 恢复，下次打开保持。
- 右键菜单：输入框里剪切、复制、粘贴、全选，选中的文字可以复制。
- 本机服务意外退出时自动重启，管理后台不整页刷新；管理后台页面崩溃时自动重新打开。特效页不受影响。

## 打开顺序

直播软件里的特效页是从星临（`127.0.0.1`）打开的网页。星临没运行时这个网页打不开，直播软件也不会自己再试，以前只能在直播软件里右键刷新。现在：

1. 特效页正常打开时，会在直播软件里登记一个很小的「看门程序」（`apps/overlay/public/sw.js`，浏览器自带的 Service Worker 功能，只在 `127.0.0.1` 和 https 下能用）。
2. 以后直播软件打开特效页时，先经过它：星临开着就照常拿最新的特效页；星临没开就显示透明的等待页，每 2 秒问一次，星临一开就刷新成特效页。
3. 要求直播软件关掉后还保留网页数据。不支持的直播软件，「直播软件输出」页的环境检测会写「自动连接」不支持。
4. 兜底提醒：桌面版每 10 秒看一次特效页在不在线；不在线时再看直播姬（`livehime.exe`）或 OBS（`obs64.exe` 等）开没开，开着超过 15 秒、特效页还是没连上，就在后台顶部和托盘提醒在直播软件里刷新。特效页从来没加过时不提醒（新手引导会带着加）。

另外，本机服务启动时不等查完开播状态（要问 B 站，网络不好时要十几秒），先开始接收特效页和后台的连接。新安装默认开机自动启动，开机后星临在托盘里先运行起来，一般不会遇到直播软件先开的情况。

## 端口

- 每次都先用 17520。被别的程序占用（或者被 Windows 保留）时，再试以前用过的端口，再往后找空的，不弹窗。
- 以前用过、这次也空着的端口一起开着（`STARFALL_EXTRA_PORTS`，最多记 4 个），直播软件里填的是新地址还是旧地址都能连上。
- 端口和平时不一样、特效页又没连上时，后台顶部提醒到「直播软件输出」复制新地址。

## 文件放在哪

| 内容 | 位置 |
|---|---|
| 程序 | `C:\Program Files\Starfall\Starfall.exe`（安装时可以改到别的盘） |
| 数据（数据库、素材、备份） | `%APPDATA%\Starfall\data` |
| 日志 | `%APPDATA%\Starfall\logs`（`main.log` 窗口和托盘，`server.log` 本机服务） |

安装和自动更新时 Windows 会弹一次「是否允许此应用对你的设备进行更改」，点「是」。卸载时会问要不要同时删除数据（素材、规则、设置和 B站登录信息），默认保留，重装后还能接着用；选删除会把 `%APPDATA%\Starfall` 整个删掉。升级和覆盖安装不会问，也不会删数据。

**国内下载新版本**：先直连 GitHub 下载；连不上、下到一半断了、或者太慢（下载 15 秒后，最近 15 秒平均每秒不到 200KB）时，自动依次换自己填的备用下载地址（「设置 → 桌面版 → 备用下载地址」）、星临的备用下载地址（`https://dl.maasky.com/desktop/`，发布时自动上传）、内置的几个公共加速站（gh-proxy.com、ghfast.top、gh.llkk.cc、ghproxy.net），窗口顶部会写明正在从哪里下载。有没有新版本、安装包的校验值都直接从 GitHub 读，GitHub 连不上时改从星临的备用下载地址读；加速站只用来传文件，下载完核对不上就不装。公共加速站随时可能停用。

从服务器版搬数据：服务器版后台「设置 → 数据 → 导出」，桌面版里「导入」。

## 命名规则

**安装包**：`Starfall-<版本号>-win-x64-setup.exe`

- 不用中文、不用空格，各部分用 `-` 连接（GitHub 发布页会改掉中文文件名，自动更新也按文件名找）
- `win` = Windows，`x64` = 64 位，`setup` = 安装程序

**版本号**：`主版本.功能版本.修复版本`

| 情况 | 怎么变 | 例子 |
|---|---|---|
| 大改版，旧数据或设置可能不兼容 | 第一位 +1 | `2.0.0` |
| 新功能 | 第二位 +1，最后一位归零 | `1.4.0` |
| 只修问题 | 第三位 +1 | `1.4.1` |
| 测试版 | 后面加 `-beta.序号` | `1.4.0-beta.1`、`1.4.0-beta.2` |

例子：`Starfall-1.4.0-beta.1-win-x64-setup.exe`、`Starfall-1.4.0-win-x64-setup.exe`。

**同一个版本，这几处必须一致**（打包时自动检查，不一致直接失败）：版本标签 `v1.4.0-beta.1`、根目录和各包 `package.json` 的 `version`（包括 `apps/desktop/package.json`）、安装包文件名。

**安装后显示的名字**：桌面图标、开始菜单、托盘、卸载列表都叫「星临」；主程序文件 `Starfall.exe`；数据文件夹 `Starfall`。

**发布页上的其他文件**：`latest.yml` / `beta.yml`（自动更新用来查新版本，名字固定）、`.blockmap`（更新时只下载变了的部分）。都不用管。

## 打包和发布（GitHub 自动完成，不占服务器）

`.github/workflows/desktop.yml`，在 GitHub 的 Windows 电脑上运行：

1. 推送版本标签：`git tag -a v1.4.0-beta.1 -m "…" && git push origin v1.4.0-beta.1`
2. GitHub 自动：装依赖 → 构建后台和特效页 → 打包本机服务 → electron-builder 打成安装包
3. 上传到发布页：标签带 `-`（测试版）标成「预发布」，不会变成首页的最新版本
   - **正式版和服务器版一起发**：同一个版本号，安装包挂在服务器版的同一个发布页上。不能只发服务器版：桌面版检查更新只看最新的正式发布，那里没有 `latest.yml` 就会报「Cannot find latest.yml」
4. 上传到星临的备用下载地址（Cloudflare R2，`https://dl.maasky.com/`）：安装包、blockmap、`latest.yml` 和服务器版代码包，见 `apps/desktop/scripts/release-r2.mjs`
   - `desktop/latest.yml` 是最新正式版；`desktop/beta.yml` 是最新的测试版或正式版（哪个新用哪个），测试版用户看它
   - 正式版留最近 3 个，测试版只留比最新正式版新的 1 个，更旧的上传时自动删掉
   - 需要仓库的 Secrets：`R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET`（R2 页面的「管理 API 令牌」，只给这个存储桶的「对象读和写」权限）
   - 上传失败不影响 GitHub 发布页，修好后在 Actions 页面对这次运行点「重新运行失败的作业」
5. 只想试打包：在 GitHub 的 Actions 页面手动运行「打包桌面版」，安装包在那次运行的页面下载（保留 14 天）；同时会试一下能不能往备用下载地址上传（不传安装包）

日常检查也在 GitHub 上跑（`.github/workflows/ci.yml`）：每次推送都做类型检查、代码规范、全部测试和构建，并在 Windows 上再跑一遍测试。

## 代码结构（apps/desktop）

| 文件 | 作用 |
|---|---|
| `src/main.ts` | 主进程：启动本机服务、窗口、托盘、开机自启、检查更新 |
| `src/server.ts` | 本机服务入口（独立进程运行，意外退出会自动重启） |
| `src/preload.ts` | 给后台页面开放的几个桌面版功能（设置页「桌面版」卡片） |
| `scripts/build.mjs` | 把三个入口各打成一个文件，准备好要放进安装包的文件 |
| `electron-builder.yml` | 安装包设置 |

本机服务通过环境变量切到桌面版：`STARFALL_DESKTOP=1`（只听 127.0.0.1、不用密码、只认本机地址和同源页面）、`STARFALL_DATA`、`STARFALL_PORT`、`STARFALL_ADMIN_DIST`、`STARFALL_OVERLAY_DIST`、`STARFALL_MIGRATIONS`。

`apps/desktop` 不在 pnpm 工作区里：Electron、electron-builder 这些打包工具只在 GitHub 打包时安装，服务器上 `pnpm install` 不会下载它们。
