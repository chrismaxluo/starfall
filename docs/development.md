# 开发约定：分支、提交与回退

这份约定的目的：**`main` 上永远是能用的版本；任何改动出了问题，都能快速、安全地退回去。**

## 1. 分支

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | **里程碑版本** | 不直接提交；只在里程碑时从 `dev` 合并，**每次合并都打标签**；部署和打包 Windows 版都从这里取；**禁止强制推送** |
| `dev` | **日常开发** | 方案文档、小改动直接提交在这里；随时保持能运行；禁止强制推送 |
| `feat/<模块>` | 大模块，例如 `feat/bili-connect`、`feat/rules-engine` | 从 `dev` 拉出，做完合并回 `dev` |
| `fix/<问题>` | 修 bug，例如 `fix/pause-bar` | 从 `dev` 拉出；线上紧急问题从 `main` 拉出，修完同时合并回 `main` 和 `dev` |
| `spike/<主题>` | 技术验证、试验性代码，例如 `spike/protocol-capture` | 从 `dev` 拉出；验证完可以直接丢弃，结论写进文档 |

```
main  ──●──────────────────────●──────────  只有里程碑：design-complete、v0.1.0……
         \                    /
dev       ●──●──●──●──●──●──●──●──●──●──  日常开发
               \        /
feat/…          ●──●──●    大模块单独开分支，做完合并回 dev
```

流程：

1. 日常开发在 `dev` 上进行；大模块从 `dev` 拉出 `feat/…`，小步提交。
2. 模块完成、测试通过后，用 `--no-ff` 合并回 `dev`，保留清晰的合并节点，然后推送。
3. 到达里程碑（例如第一期可用），汇报并确认后，把 `dev` 用 `--no-ff` 合并进 `main`，打标签，推送。

## 2. 提交

- **小步提交**：一次提交只做一件事，方便单独回退。
- **提交信息用中文**，第一行说清楚改了什么，比如 `规则引擎：粉丝牌分档自动切分`，需要时再写几行说明原因。
- 提交前确认没有带上运行数据（数据库、上传的素材、B 站登录信息），这些已经在 `.gitignore` 里排除。

## 3. 标签（里程碑）

每到一个重要节点就打标签，作为回退的锚点：

| 标签 | 含义 |
|---|---|
| `design-complete` | 需求已确认，界面设计预览与开发约定完成，尚未开始编码 |
| `v0.1.0`、`v0.2.0`…… | 开发过程中的可用版本 |
| `v1.0.0` | 第一期正式版 |

## 4. 回退

先看历史，找到要回到的位置：

```bash
git log --oneline --graph --decorate -20
git tag                       # 查看所有里程碑
```

按情况选一种：

| 情况 | 命令 | 说明 |
|---|---|---|
| 还没提交的改动不要了 | `git restore <文件>`，全部放弃用 `git restore .` | 只影响工作区 |
| 撤销某一次**已推送**的提交 | `git revert <提交号>` | **推荐**：生成一个"反向提交"，历史保留，可以再撤回 |
| 撤销一次合并进来的功能 | `git revert -m 1 <合并提交号>` | 在 `dev` 或 `main` 上把整个功能一次性撤掉 |
| 功能分支里最近几次提交不要了（**未推送**） | `git reset --hard <提交号>` | 会丢掉之后的提交，只在自己的分支上用 |
| 只是想看看旧版本 | `git switch --detach design-complete` | 看完用 `git switch main` 回来，不改变任何东西 |
| 整个项目回到某个里程碑重新开始 | `git switch -c restart-from-x <标签>` | 从旧版本拉一个新分支，原来的历史不动 |
| 某个文件恢复成旧版本 | `git restore --source <提交号或标签> <文件>` | 只改这个文件 |

原则：**已经推送到 GitHub 的历史用 `revert`，不用 `reset` + 强制推送。**

## 5. 不在 git 里的东西

这些不进仓库，需要单独备份（第一期会实现自动备份）：

| 内容 | 位置（正式开发后） | 备份方式 |
|---|---|---|
| 数据库（规则、事件记录） | `data/` | 每天自动备份；可在设置页导出配置 |
| 上传的素材和音效 | `data/` | 同上 |
| B 站登录信息 | `data/` | **不备份到任何外部位置**，丢了重新扫码即可 |
| 服务器环境（Node.js 等） | 系统 | 按 README 和部署文档重建 |
